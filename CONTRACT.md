# deadheat Contract

This Contract is the executable spec for deadheat. Every obligation is checked by a named test or by a named check. The Contract is reported as met or not met in the README programme status.

## Setup obligations

- SETUP-1. The repo carries AGENTS.md with the canonical template verbatim
  above its marked line and the repo annex below it. Test,
  tests/test_setup.py.
- SETUP-2. The README programme status states the closed round count out

  and U+2013 in every Markdown and text file in the repo and requires
  zero of each. The scan runs in the local gate and in CI.

## First slice obligations, stub form

The full Contract for the first slice is the first build act of this repo. These stubs state the obligations the first slice will be held to, in the form they will be extended.

- DH-1. A race holds exactly two attempts at the same task, each attempt in its own environment, and each attempt recording its suite result, its elapsed time, and its token spend where the runner reports it. Test, the first slice tests.
- DH-2. The winner is the first attempt whose full suite is green. If both suites finish green the earlier finish wins, and if neither goes green there is no winner and the race says so. Test, the first slice tests.
- DH-3. The losing attempt gets a rendered funeral naming the task, the winner, and the margin, and its diff is kept as a patch that can be adopted or discarded. Test, the first slice tests.
- DH-4. Season standings persist across races in one standings file, recording wins, losses, and spend per model. Test, the first slice tests.

## First slice obligations, full form

This section extends the stub section above, which stays standing as the record of the form these obligations started in. Where the full form and a stub read a rule differently, the full form governs.

- DH-1. A race record is one JSON object holding a task label under the field task and exactly two attempts under the field attempts. Each attempt is an object holding a model label under model, an environment label under environment, a suite result under result, a token spend under tokens, and the attempt diff under patch. The suite result is one of the words green, red, and unfinished, where green and red mean the suite finished and unfinished means it did not. The field finished_at holds the elapsed seconds at which the suite finished, and it is present exactly when the suite finished, so a green or red attempt always carries it and an unfinished attempt never does. The tokens field is always present and holds a non negative integer count, or null when the runner did not report spend. The patch field holds the attempt diff as text, kept verbatim, and it may be empty. Fields the shape does not name are ignored. The loader takes recorded race text or a recorded race file and returns the race and a list of defects, and it names every malformed field it finds in one pass and never raises on malformed content. The defect vocabulary is fixed, and a test pins each phrase. Test, tests/test_races.py.
- DH-1, the local runner. Attempts are produced locally in this slice. The runner runs one shell command per attempt, each in its own directory under one race workspace, and builds the attempt record from the run. The command may write a file named result.json in its directory holding an object that may name the suite result and the token spend, and a named result wins over the exit code while an unnamed result falls back to the exit code, where code zero is green and any other code is red. A result file that cannot be read as that shape is ignored. The token spend comes from the result file when it names a non negative integer, and is null otherwise. When the runner timeout passes before the command ends, the command is stopped and the attempt is unfinished, with no finished_at and no read of the result file. The elapsed seconds are measured by the runner on a monotonic clock and recorded as finished_at when the suite finished. The patch is the text of a file named patch.diff in the attempt directory when the command wrote one, and the empty string otherwise. Environments in this slice are local directories. Running attempts inside switchyard environments is a later obligation, and nothing in this slice claims it. Test, tests/test_runner.py.
- DH-2. The winner of a race is decided from the loaded record alone. A green attempt beats a red or unfinished attempt. When both attempts are green the earlier finished_at wins, and on an exact tie of finish times the attempt that stands first in the record wins. When neither attempt is green there is no winner. The loser is the other attempt when a winner exists, and there is no loser when there is no winner. The race report and the funeral both state the outcome, naming the winner or stating that there is no winner, and neither is ever left blank. Test, tests/test_races.py.
- DH-3. The funeral is a deterministic text rendering of one race, a pure function of the record, byte identical for the same record. Its first line names the task. It then names the winner with its model, its environment, and its finish, or states that there is no winner and neither suite went green. When a loser exists it names the loser with its model, its environment, and its outcome. When both attempts carry finished_at it carries a margin line naming the seconds between the two finish times. The race report is a deterministic text rendering that stands ahead of the funeral in the race command output, with one line per attempt naming the model, the environment, the outcome, and the token spend or its absence, and a verdict line naming the winner or stating that there is no winner. The loser patch is the patch text of the losing attempt, kept verbatim. Adopting it is a file operation that writes that text into a patches folder, under a file name built from the task label and the loser model label, each reduced to a slug of lower case letters and digits joined by single dashes, with a label that reduces to nothing becoming the word unnamed, and the two slugs joined as task slug, a dash, model slug, and the suffix .patch. Discarding it is a file operation that removes that file when it stands there and succeeds either way. Both operations require a loser and refuse a race that has none. Seconds render exactly at up to six decimal places, and a nonzero value that rounds to zero at that precision renders at full precision. Test, tests/test_races.py and tests/test_cli.py.
- DH-4. Season standings live in one JSON file holding an object under the field models, keyed by model label, where each entry holds the integer counts wins, losses, and no_results, the integer total tokens, and the integer count tokens_unreported. Recording one race is a pure function from the standings and the race to new standings, and the input standings are never mutated. A race with a winner adds one win to the winner model and one loss to the loser model. A race with no winner adds one no result to both models. Token spend adds per attempt, where a reported count adds to total tokens and a null count adds one to tokens_unreported and nothing to total tokens, so unreported spend is never read as zero spend. The standings table is a deterministic rendering with one line per model in label order, naming the wins, the losses, the no results, the total tokens, and the unreported count. The race command updates a standings file when one is named, starting from empty standings when the file does not stand there, and refusing without writing when the file stands there and is malformed. Test, tests/test_races.py and tests/test_cli.py.
- The command line surface. The race command takes a recorded race file, prints the race report and the funeral, and exits with status one while printing the defects when the race is malformed, and it takes an optional standings file name that it updates after a good race. The adopt command takes a recorded race file and a patches folder and writes the loser patch there. The discard command takes a recorded race file and a patches folder and removes the loser patch file when it stands there. The standings command takes a standings file and prints the standings table, and exits with status one while printing the defects when the file is malformed. The same inputs always print the same bytes. Test, tests/test_cli.py.
- Amendment to SETUP-3. The scan scope is stated as the widened rule. The scan counts the two codepoints in files whose suffix is .md, .txt, .py, .json, .toml, .yml, or .yaml, and in extensionless files, and it skips the ignored environment and build directories. This amendment records line uniformity with the paceghost and corked Round 1 repairs, where the same widening landed, and the original SETUP-3 text stays standing above as the record of the narrower statement. Test, tests/test_scan.py.
- Amendment to the setup CI pin. The setup test that pins CI to the local gate cuts every line of the workflow file at its first hash character before it searches for the two gate commands, so a gate command surviving only inside a comment cannot satisfy the pin. This amendment records the same line uniformity with the paceghost and corked Round 1 repairs. Test, tests/test_setup.py.

## Round 2 obligations, full form

This section states the Round 2 obligations in full form. Every Round 1 section above stays standing, and where this section and a Round 1 section read a rule differently, this section governs for the races it names and the Round 1 reading stands for every other race.

- DH-5. A finished race sits in the close call band when the two attempts hold the same suite result and that result is not green, or when both attempts went green and their finish times differ by more than zero and by no more than five percent of the slower finish. An exact tie of green finish times is not a close call, and the Round 1 rule for a tie stands. The band is a deterministic test on the recorded figures alone. The margin comparison is computed on exact fractions of the recorded figures, multiplying the gap by twenty and comparing it against the slower finish, so no rounding at any precision can move a race across the band edge. A race record may carry an adjudication entry under the field adjudication, holding the adjudicator label under adjudicator, the chosen attempt under chosen, a confidence figure under confidence, and a one line reason under reason. The chosen attempt is named by its model label, and when both attempts carry that label the attempt that stands first in the record is the chosen one. The loader validates the entry and never raises. An entry that is not an object draws the defect field adjudication is not an object. An absent entry field draws the defect adjudication is missing field and the field name. A field of the wrong kind draws the defect adjudication field and the field name and has the wrong type. An empty text field draws the defect adjudication field and the field name and is empty. A text field holding an unpaired surrogate draws the defect adjudication field and the field name and holds an unpaired surrogate. A confidence that is not a finite number draws the defect adjudication field confidence is not a finite number. A confidence below zero or above one draws the defect adjudication field confidence is outside the range zero to one. A chosen label naming neither attempt draws the defect adjudication field chosen names no attempt in this race. A reason holding a newline or a carriage return draws the defect adjudication field reason holds a newline. Fields the entry does not name are ignored, and a race carrying any adjudication defect returns no race. A recorded adjudication in this round is a synthetic fixture in the envelope shape the roadmap names. The live call that would produce a real one is later work, and nothing in this round makes one. Test, tests/test_close_calls.py.
- DH-5, the winner rule step. The winner rule gains one step ahead of the Round 1 reading. A race in the close call band whose adjudication entry carries a confidence meeting the threshold is decided for the chosen attempt, and the other attempt is the loser. The threshold is four fifths, and the comparison is exact on the recorded figure, multiplying the confidence by five and comparing it against four, so a recorded confidence of 0.8 meets the threshold and no rounding can move a verdict across it. A race in the band with no adjudication entry stands as no result. A race in the band whose entry carries a confidence below the threshold stands as no result, and the adjudication is an abstention. A race outside the band is decided by the Round 1 rule exactly as Round 1 left it, an adjudication entry it carries is ignored, and the race report states that the entry was not needed. The standings record an adjudicated race as a win and a loss and record an undecided close call as a no result for both models, exactly as DH-4 already provides. Test, tests/test_close_calls.py.
- DH-5, the close call rendering. The race report names a race in the band as a close call on a line after the verdict line, stating that the adjudication decided it and naming the adjudicator, the chosen model, and the confidence, or that the adjudication abstained and naming the adjudicator and the confidence, or that no adjudication is on record. A race outside the band that carries an entry states on the same line that the entry was not needed. The funeral of a race decided by adjudication carries a line before the margin line stating that the adjudication decided it and naming the adjudicator, the chosen model, and the confidence. The funeral of an undecided close call carries a line before the margin line stating that the race stands as a dead heat and whether no adjudication is on record or the adjudication abstained, naming the adjudicator and the confidence in the abstention case. The funeral line stating there is no winner reads that both suites went green inside the close call band when both attempts went green, and keeps the Round 1 wording otherwise. A confidence renders the way seconds render under DH-3. Every other report and funeral line keeps its Round 1 shape, and a race that carries no entry and sits outside the band renders exactly as Round 1 left it. Test, tests/test_close_calls.py and tests/test_examples.py.
- DH-6. A series file is one JSON object holding the task family label under task, the two models under models, the wins target under wins_target, and the recorded races under races. The models field holds a list of exactly two distinct non empty labels. The wins target is a positive integer. The races field holds a list of race records in the DH-1 shape, and the list may be empty. The series loader names every defect it finds and never raises. A models field of the wrong kind draws the defect field models has the wrong type. A models list holding any count other than two draws the defect field models must hold exactly two models. A models entry of the wrong kind draws the defect models entry and its index and has the wrong type, an empty entry draws models entry and its index and is empty, and an entry holding an unpaired surrogate draws models entry and its index and holds an unpaired surrogate. Two entries naming the same model draw the defect field models names the same model twice. A wins target of the wrong kind draws the defect field wins_target has the wrong type, and a wins target below one draws the defect field wins_target is not positive. The task field and the races field draw the same defect phrases the race loader uses for a field of that name. A race entry that is not an object draws the defect race and its index and is not an object. A malformed race names its own defects each prefixed with race and its index. A race naming a model outside the two series models draws the defect race and its index and names a model outside the series. A race whose two attempts name the same model draws the defect race and its index and names the same model twice. A file that cannot be read and text that is not JSON draw the same defects the race loader names for them. Test, tests/test_series.py.
- DH-6, the series report. The series report is a deterministic text rendering of one series, a pure function of the loaded series. Its first line names the task family after the word series. Its second line names the two models and the wins target. It then renders one line per race in record order, counting races from one, naming the race task and its outcome as a win for one model or as no result, and after each race a tally line naming the wins of each model in the order the models field names them and the count of no results so far. The series is decided at the race where a model first reaches the wins target. A race recorded after the deciding race is rendered as beyond the decision, carries no tally line, and changes nothing. The closing line names the series winner when the series is decided, and states that the series stands unfinished and names the wins target when no model has reached it. The winner of each race is read by the winner rule of DH-2 as extended by DH-5, so an adjudicated close call counts for the chosen model and an undecided close call counts as a no result for both. Test, tests/test_series.py.
- The Round 2 command line surface. The closecall command takes a recorded race file and prints whether the race sits in the close call band and why, then what the adjudication entry does to the race, then the verdict line the race report uses, and it exits with status one while printing the defects when the race is malformed. The series command takes a series file and prints the series report, and exits with status one while printing the defects when the series is malformed. The same inputs always print the same bytes. Test, tests/test_close_calls.py and tests/test_series.py.

## The pilot envelope scan exemption

The Round 3 pilot records its envelopes exactly as their routes
returned them under examples/pilot/envelopes, and a returned
envelope can carry characters SETUP-3 forbids in the repo own
text, inside the model own words. The codepoint scan therefore
does not cover that one directory. The exemption is the
directory alone, and the scan keeps covering every other path
in the tree, including the pilot races and records standing
beside the envelopes. A recording is never rewritten or escaped
to satisfy the scan, because the fixture claim is that the
envelope data is exactly what its route returned.
